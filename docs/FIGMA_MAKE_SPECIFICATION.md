# Bingify サービス仕様書 - Figma Make用プロンプト

このドキュメントは、BingifyのUI/UXデザインをFigma Makeで作成する際に使用できる包括的なサービス仕様書です。

## サービス概要

### 基本情報

**サービス名**: Bingify
**公式URL**: https://bingify.space/
**GitHub**: https://github.com/ykzts/Bingify

**サービス説明**:
配信者・コミュニティ向けリアルタイム・ビンゴ大会ウェブアプリケーション。ストリーマーやコミュニティマネージャーがオンラインでビンゴイベントを開催し、参加者がリアルタイムで同期されたビンゴカードを使って参加できるプラットフォームです。

### コアバリュー

1. **リアルタイム同期**: Supabase Realtimeを使用し、抽選結果が全参加者に即座に反映
2. **コミュニティ向け**: 配信者とコミュニティに最適化された設計
3. **ブラウザーベース**: アプリインストール不要、URLで即参加可能

### ターゲットユーザー

- **配信者（ホスト）**: YouTubeやTwitchで配信するストリーマー
- **コミュニティマネージャー**: イベント運営者
- **参加者**: 視聴者やコミュニティメンバー

## ページ構成・URL構造

### 認証状態

Bingifyは認証の有無でアクセスできる機能が異なります。

**認証方式**: Supabase Auth + OAuth (Google、Twitch)

### 全体URL構造

```
/ (ルート)
├── /[locale]/ (多言語対応: en, ja)
│   ├── / (トップページ - 誰でもアクセス可)
│   ├── /login (ログインページ - 未認証のみ)
│   ├── /setup (初回セットアップ - 認証後初回アクセス時)
│   │
│   ├── /dashboard (ダッシュボード - 認証必須)
│   │   └── /spaces/[id] (スペース管理画面 - 所有者のみ)
│   │
│   ├── /spaces/[id] (参加者画面 - 認証必須)
│   │
│   ├── /@[share_key] (公開URL - 認証必須、内部的に/spaces/[id]にrewrite)
│   │
│   ├── /settings (ユーザー設定 - 認証必須)
│   │   ├── /profile (プロフィール設定)
│   │   ├── /avatar (アバター設定)
│   │   ├── /connections (連携アカウント)
│   │   └── /account (アカウント管理)
│   │
│   ├── /admin (管理画面 - 管理者のみ)
│   │   ├── / (管理ダッシュボード)
│   │   ├── /spaces (スペース管理)
│   │   ├── /users (ユーザー管理)
│   │   ├── /announcements (お知らせ管理)
│   │   ├── /general (一般設定)
│   │   ├── /auth-providers (認証プロバイダー設定)
│   │   ├── /resource-limits (リソース制限設定)
│   │   ├── /gatekeeper (アクセス制御設定)
│   │   ├── /secrets (シークレット管理)
│   │   └── /mail (メール設定)
│   │
│   ├── /notifications (通知一覧 - 認証必須)
│   ├── /announcements (お知らせ一覧 - 誰でもアクセス可)

│   ├── /privacy (プライバシーポリシー)
│   └── /terms (利用規約)
│
└── /screen/[token] (表示専用画面 - 認証不要、配信用)
```

## 主要ページ詳細仕様

### 1. トップページ (`/`)

**目的**: サービスの説明とCTA（行動喚起）

**セクション構成**:

#### 1.1 Hero Section

- **背景**: パーティクルアニメーション（浮遊する円形の装飾要素）
- **バッジ**: 3つの小さなバッジ（例: "無料", "アプリ不要", "リアルタイム"）
- **タイトル**: 大きな見出し（ハイライト付き）
  - 例: "配信者のための **リアルタイムビンゴ**"
- **説明**: 2行のサブテキスト
- **CTA**: 大きな紫のボタン（例: "無料で始める"）

#### 1.2 Features Section

- **見出し**: セクションタイトルとサブタイトル
- **3つの特徴カード**:
  1. **リアルタイム同期** (アイコン: Zap)
  2. **コミュニティ向け** (アイコン: Users)
  3. **アプリ不要** (アイコン: Globe)
- **カードデザイン**:
  - 角丸（rounded-2xl）
  - ホバー時に上昇＆スケール
  - アイコンはホバー時に360度回転
  - 右上に装飾用の円形グラデーション

#### 1.3 FAQ Section

- **アコーディオン形式**
- **よくある質問**が折りたたみで表示される

#### 1.4 Support Section

- **見出し**: "サポートについて"
- **説明文**: スポンサーシップ案内
- **CTA**: "GitHub Sponsorsで支援する"ボタン

**レイアウト**:

- 中央揃え
- 最大幅: 6xl (1280px)
- 余白: px-6, py-20

### 3. ダッシュボード (`/[locale]/dashboard`)

**目的**: ユーザーのスペース一覧と新規作成

**セクション構成**:

#### 3.1 スペース作成フォーム

- **タイトル**: "新しいスペースを作成"
- **入力フィールド**:
  - **スペース名** (必須)
  - **共有キー** (必須、英数字とハイフン、リアルタイム重複チェック)
  - **説明** (任意)
- **プレビュー**: 共有キーの完全な形式を表示（例: `my-party-20251224`）
- **送信ボタン**: "作成する"

#### 3.2 スペース一覧タブ

**タブ構成**:

1. **主催中** (Active Hosted)
2. **参加中** (Participated)
3. **下書き** (Draft)
4. **終了済み** (Closed)

**スペースカード**:

- **タイトル**
- **共有キー**: `@[share_key]` 形式
- **ステータス**: アクティブ/ドラフト/終了
- **作成日時**
- **アクションボタン**: "管理する" / "参加する"

**空状態**:

- アイコン（例: FileText, Users）
- "まだスペースがありません"
- 説明文

### 4. スペース管理画面 (`/[locale]/dashboard/spaces/[id]`)

**目的**: ホストがビンゴイベントを管理・実行する画面

**権限**: スペース所有者のみアクセス可能

**セクション構成**:

#### 4.1 ヘッダー

- **スペース名**
- **ステータスバッジ**: ドラフト/アクティブ/終了
- **アクションボタン群**:
  - 設定
  - 表示設定
  - 閉じる

#### 4.2 URL共有セクション

- **参加者用URL**: `@[share_key]` 形式
- **QRコード**: モバイル参加用
- **コピーボタン**
- **表示専用URL**: `/screen/[token]` (配信用)

#### 4.3 ビンゴ抽選セクション

- **大きな抽選ボタン**: "抽選する"
- **現在の番号表示**: 最後に抽選された番号
- **履歴**: 抽選済み番号のリスト（時系列順）

#### 4.4 参加者ステータス

- **参加者数**: リアルタイム更新
- **ビンゴ達成者**: リスト表示
- **参加者一覧テーブル**:
  - ユーザー名
  - アバター
  - カード詳細ボタン

#### 4.5 スペース設定

- **基本設定**:
  - タイトル
  - 説明
  - 最大参加者数
- **表示設定**:
  - 背景色（配信用クロマキー対応）
  - フォントサイズ
- **お知らせ管理**: スペース内お知らせの作成・編集
- **管理者追加**: 複数管理者の設定
- **Danger Zone**: スペース削除

### 5. 参加者画面 (`/[locale]/spaces/[id]` または `/@[share_key]`)

**目的**: 参加者がビンゴカードを表示し、ゲームに参加

**権限**: 認証必須

**セクション構成**:

#### 5.1 ランディング（参加前）

- **スペース情報**:
  - タイトル
  - 説明
  - 主催者名
- **参加ボタン**: "ビンゴカードを取得"
- **注意事項**: 参加後のカード固定など

#### 5.2 ビンゴカード表示（参加後）

- **5x5グリッド**:
  - 中央は "FREE" スペース
  - 各マスに数字（1-75）
  - 抽選済み番号はハイライト表示
- **リアルタイム更新**: 抽選番号が自動反映
- **ビンゴ達成時**: 紙吹雪アニメーション（canvas-confetti）
- **ビンゴライン表示**: 達成したラインをビジュアル表示

#### 5.3 履歴・ステータス

- **抽選済み番号**: 一覧表示
- **ビンゴ達成状況**: 達成したライン数

### 6. 表示専用画面 (`/screen/[token]`)

**目的**: 配信画面でのオーバーレイ表示

**権限**: 認証不要（view_tokenで認証）

**特徴**:

- **クロマキー対応**: 緑または青の背景選択可能
- **シンプルUI**: 最小限の情報のみ表示
- **リアルタイム更新**: 抽選番号が即座に反映
- **配信者向け**: OBSやXSplitで使いやすいレイアウト

**表示内容**:

- **現在の番号**: 大きく表示
- **抽選履歴**: 最近の番号
- **スペース情報**: タイトルのみ

**デザイン**:

- 背景色: クロマキーグリーン (#00ff00) またはブルー (#0000ff)
- テキストは高コントラストで読みやすく
- 余計な装飾は排除

**権限**: 管理者ロールのみ

#### 8.3 ユーザー管理 (`/admin/users`)

- **ユーザー一覧**: テーブル形式

- **円形**: rounded-full

#### Badge

- **角丸**: rounded-fullまたはrounded-md

- **位置**: 右下または上部中央

- **アクション**: 閉じるボタン

- **アニメーション**: 回転

## 国際化 (i18n)

### サポート言語

- **英語 (en)**
- **日本語 (ja)**

### 実装方式

- **next-intl**: メッセージ管理
- **メッセージファイル**: `messages/en.json`, `messages/ja.json`
- **URL構造**: `/[locale]/...`
- **言語切り替え**: ヘッダーにLanguage Switcher

### 翻訳が必要な要素

- **UI文言**: ボタン、ラベル、説明文
- **エラーメッセージ**: フォームバリデーション、サーバーエラー
- **メール**: 通知メール、確認メール
- **お知らせ**: 管理者が作成するお知らせ

## データフロー・状態管理

### リアルタイム同期

**Supabase Realtime**を使用:

1. **抽選**: 管理者が抽選ボタンをクリック
2. **DB更新**: `called_numbers` テーブルに挿入
3. **Realtime配信**: 全クライアントに即座に配信
4. **UI更新**: 各参加者のビンゴカードが自動更新

### 認証フロー

1. **OAuth開始**: ユーザーがGoogle/Twitchボタンをクリック
2. **リダイレクト**: プロバイダーの認証画面へ
3. **コールバック**: 認証後、Supabaseが処理
4. **セッション作成**: Cookieにセッション保存
5. **リダイレクト**: 元のページまたはダッシュボードへ

### フォーム送信

1. **クライアント検証**: Zod + TanStack Form
2. **サーバーアクション**: Next.js Server Actions
3. **DB操作**: Supabaseクライアント
4. **レスポンス**: 成功/エラーメッセージ
5. **UI更新**: フォームリセットまたはエラー表示

## セキュリティ

### Row Level Security (RLS)

SupabaseのRLSを使用し、データアクセスを制限:

- **spaces**: 所有者のみ編集可能、認証済みユーザーは閲覧可能
- **bingo_cards**: 自分のカードのみアクセス可能
- **called_numbers**: 全員閲覧可能、スペース所有者のみ追加可能

### 認証保護

- **Middleware**: 認証が必要なルートを保護
- **Server Actions**: 認証状態をサーバーで検証
- **OAuth**: Google、Twitchの公式SDK使用

### XSS対策

- **エスケープ**: ユーザー入力は全てエスケープ
- **Content Security Policy**: 適切なCSP設定

### CSRF対策

- **SameSite Cookie**: CSRFトークン不要
- **Supabase Auth**: 組み込みの保護機能

## Figma Makeでの推奨アプローチ

### デザイン制作時の推奨順序

1. **デザインシステム構築**:
   - カラーパレット（Purpleベース）
   - タイポグラフィ（Nunito）
   - コンポーネントライブラリ（shadcn/uiベース）
   - アイコンセット（Lucide React）

2. **コンポーネント設計**:
   - ボタン、カード、ダイアログ、フォーム、テーブル、タブ、アバター、バッジ
   - 各コンポーネントのバリエーション・状態を網羅

3. **ページデザイン**:
   - トップページ（Hero, Features, FAQ, Support）
   - ログインページ
   - ダッシュボード
   - スペース管理画面
   - 参加者画面
   - 表示専用画面
   - 設定画面
   - 管理画面

4. **レスポンシブ対応**:
   - デスクトップ（1280px+）
   - タブレット（768px-1279px）
   - モバイル（~767px）

5. **インタラクション定義**:
   - ホバーエフェクト
   - クリックフィードバック
   - アニメーション
   - トランジション

6. **ダークモード**:
   - 全ページのダークモードバリエーション
